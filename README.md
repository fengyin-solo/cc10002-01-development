# 数据指标分析平台

面向指标口径定义、多维度聚合分析、AB实验评估、数据服务发布与数据应用交付的数据指标分析平台。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 指标口径版本化与发布

指标定义支持按指标编号维护多份口径版本（草稿 / 已发布），并与聚合查询联动：

- `GET/POST /api/metricdef/versions`：按指标编号列出、登记口径版本；版本号由系统
  在锁内按指标编号分配（`v1`、`v2`…），并发登记不会撞号。
- `GET /api/metricdef/versions/{id}/diff`：与上一相邻版本对比计算公式、统计粒度、
  时间窗口类型、精度位数。
- `POST /api/metricdef/releases`：发起发布，正在使用该指标的聚合规则进入影响确认
  范围，生成待确认批次；同一指标同时只允许一个待确认批次。
- `POST /api/metricdef/releases/{id}/confirm`：确认发布。版本状态与全部规则的
  确认结果（保留旧版 / 切换新版）作为同一业务提交生效；任何校验不通过都不落半个
  改动；重复提交同一批次直接返回已生效结果，不产生重复版本。
- `POST /api/aggregation/{id}/execute`、`/recalculate`：按规则当前确认的口径版本
  执行 / 重算，结果记录（`GET /api/aggregation/results`）保留当时的口径版本、
  版本来源与计算公式快照；只有主动执行或重算才产生新结果。
- 既有样例里的非规范版本文字（如「指标定义样例1」）归一化失败，标记为「未归档」，
  不会被当成最新版本。
